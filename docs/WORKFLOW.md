# Production workflow

## 阶段 A：先做账号身份，不急着批量发

1. 修改 `brand/default/brand.yaml` 的账号名、颜色、背景、镜头、签名符号和禁用规则。
2. 执行 `python -m app.cli brand-preview` 检查中文字体、边距和视觉骨架。
3. 用 10–20 个真实标题在 Mock 模式生成结构样张。
4. 选择 6–12 张你真正认可、并拥有使用权的视觉样张，上传为 Approved References。
5. 冻结为 `version: 1.0.0`，正式发帖期间不要每篇都改风格。

## 阶段 B：一个标题如何进入生产

### 1. 写 StoryBrief

只输入标题仍然不够，至少补齐：

- 目标用户；
- 发生场景；
- 真实限制；
- 本组内容承诺；
- 已有来源；
- 不允许出现的功效话术。

### 2. 审查 ContentPlan

真实模型生成后，先检查 `plan.json`：

- 每一页是否只做一件事；
- 是否存在重复要点；
- 数量是否和标题一致；
- 事实声明是否标记 `needs_verification`；
- 视觉主体是否能真实拍摄或生成；
- 最后一页是否说明来源与边界。

不要在这一阶段因为“图片很好看”而跳过事实审查。

### 3. 审查 VisualBrief

每一页都要能回答：

- 主体是什么；
- 有几个；
- 是完整、切开、煮熟、冷藏还是分装状态；
- 哪些细节必须被看见；
- 什么东西绝对不能出现；
- 哪一块必须留白给中文排版。

### 4. 生成无文字素材

图片模型不负责中文。这样可以避免：

- 汉字错乱；
- 每篇字体不同；
- 标题位置变化；
- 页码和标签不统一；
- 模型为了排字破坏食物构图。

### 5. 审查与定向重试

审查报告在 `reviews/`。重试 Prompt 只修正已发现的问题，例如：

- 数量错；
- 缺少必须出现项；
- 出现包装或文字；
- 文字安全区被占；
- 画幅异常；
- 图片接近空白。

不要每次完全重写 Prompt，否则风格漂移会更严重。

### 6. 本地排版

`Renderer` 固定：

- 1080×1440 画布；
- 字体候选与字号层级；
- 边距、卡片圆角、页码；
- 橙红圆形切角、墨绿弧线和叶形；
- 页脚披露和事实核验提示。

### 7. 发布后回填结果

当前版本保存生产历史，但不自动抓取平台数据。建议在项目目录新增 `performance.json`：

```json
{
  "published_at": "2026-08-21",
  "views_24h": 0,
  "likes_24h": 0,
  "saves_24h": 0,
  "follows_24h": 0,
  "notes": "封面点击高，但关注转化低"
}
```

后续迭代应优先修改选题和信息价值，不要因为单篇数据差就立刻换整套视觉风格。
