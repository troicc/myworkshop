# Brand system

## 一致性不是“每张图长一样”

推荐把账号视觉拆成三层：

- **不可变层（约 70%）**：色彩、字体、版式骨架、背景材质、镜头高度、光线、签名符号。
- **主题层（约 20%）**：食材、用品、道具、标题数字、局部构图。
- **实验层（约 10%）**：新栏目、新视角或小范围版式实验。

用户记忆来自不可变层持续重复，而不是把同一模板换八种食物。

## Brand DNA 字段

`brand.yaml` 既是设计配置，也是 Prompt 来源：

- `palette`：最终排版颜色；
- `typography`：本机字体候选与层级；
- `layout`：边距、标题行数、圆角、页脚；
- `visual`：图片模型使用的镜头、光线、背景、材质与禁止项；
- `copy`：账号名、口吻、披露文案和页脚。

所有字段会计算 SHA-256 指纹，写入 manifest。只要配置改变，Style ID 就会改变，便于追踪哪一版风格产生了哪一篇内容。

## Approved References

参考图不是“越多越好”。推荐：

1. 先用文字 Brand DNA 生成 20 张候选；
2. 人工删掉不稳定或不属于账号的图片；
3. 保留 6–12 张形成参考库；
4. 参考库需要覆盖不同主题，但必须保持同一镜头、色温和背景语言；
5. 模型支持图片编辑时可作为输入；不支持时仍用于视觉审查和人工比对。

## 版本策略

- 小文案调整：`1.0.0 → 1.0.1`
- 新增或调整版式：`1.0.x → 1.1.0`
- 完全更换账号视觉：`1.x → 2.0.0`

正式测试期至少连续发布 15–30 篇再判断一版 Brand DNA 是否有效，避免每三篇就换风格。
